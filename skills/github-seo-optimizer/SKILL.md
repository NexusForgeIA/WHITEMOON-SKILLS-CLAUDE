# github-seo-optimizer

*Cluster: Keywords & Links . Part of the 17 SEO Skills set by Vicky Lalwani, Digital Marketing Director.*

## Purpose

Make a GitHub repository discoverable - optimizing its README, description, topics, and metadata so it ranks in GitHub search, earns recommendations, and surfaces in Google.

## When to use

- The user has a repo they want found and starred
- Launching an open-source project or developer tool
- A repo gets no traffic or stars despite being useful
- Optimizing a portfolio or company open-source presence

## Inputs required

- Repository URL (required)
- Optional: the primary keywords developers would search to find this tool
- Optional: competing or similar repos to benchmark against

## Step-by-step instructions

1. Fetch the repo. Read the current README, description, topics, and About section.
2. Identify the primary keywords: what would a developer type to find this tool? Check how similar successful repos describe themselves.
3. Optimize the repo description (the one-line summary): clear, keyword-rich, benefit-led, under the length limit.
4. Optimize topics/tags: add the relevant, searched topics GitHub recognizes (these power GitHub's own discovery and topic pages). Aim for the maximum useful set.
5. Optimize the README for both humans and search: a clear keyword-rich H1 and intro, a concise what-it-does and why, install and usage sections, and headings that match how people search. The README is what Google indexes.
6. Recommend supporting signals: a clear license, relevant section anchors, social-preview image, and internal links to docs. Output the rewritten description, the topic list, and the optimized README sections.

## Output format

Three deliverables: the rewritten repo description, the recommended topics/tags list, and the optimized README sections (H1, intro, headings) - all paste-ready. Plus a short list of supporting discovery signals to add.

## Quality checklist

- [ ] The repo description is clear, keyword-rich, and within length limits
- [ ] Topics use real GitHub-recognized tags that developers search
- [ ] The README opens with a keyword-rich H1 and a clear what/why
- [ ] README headings match how developers actually search
- [ ] Supporting signals (license, social preview, anchors) are recommended

## Optimization notes

GitHub discovery has two doors: GitHub's own search and topic pages (powered heavily by topics and description) and Google (which indexes the README). Optimize for both. The README's first screen does most of the work - if a developer can't tell what the tool does and why to use it in five seconds, they bounce, stars or not.
